The criteria this shape of documentation most often fails, and how this template addresses
each one:

- **Content type consistency** — an article stays inside ONE content type. This artefact is
  **Reference** content. The single deliberate exception is Getting Started: a short opening
  sequence that orients the reader, not a full tutorial.
- **Reference Content** — structured, not narrated: signature, parameter table, return table,
  error table, and a Behaviour section that states meaning rather than restating arguments.
- **Error Reference** — errors documented per exception, separately from troubleshooting.
- **Conceptual content** — carried by the Overview, which explains the problem and the design
  intent in three short paragraphs rather than one line.
- **Further Reading and Next Steps are required**, not optional: they are what makes the page
  a hub. Name the related entities explicitly.
- **Content order** — prerequisites before usage; reference material grouped together.

## Output rules — read before writing

1. **Emit the sections below in the given order.** For conditional sections, drop the whole
   section when the condition fails: no "None", no "N/A", no empty table.
2. **`## Behaviour` is mandatory** and must cover all five families — what it does, inputs,
   outputs, failures, side effects — one labelled line each. When the source does not show a
   family, say so in one clause instead of dropping the line.
3. **Declare the content type once in Metadata and stay inside it.**
4. **Reference material is tabular**: signature in a code fence, parameters / returns /
   errors in tables.
5. **Errors get their own table keyed by exception**, derived from the raise statements in
   the evidence above. Never invent an exception the source cannot raise.
6. **No invented facts** — no version, date, author, license, benchmark, or behaviour the
   source does not show.
7. **Length: 250–400 words for a function or method, 500–700 for a class.**
8. **Headings: H1 then H2 only.** Titles stay under 80 characters; the qualified name lives
   in Metadata, not in the H1.
9. **Do not copy the dependency source blocks** into the document; refer to them.
