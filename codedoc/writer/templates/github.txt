## Documentation Standards

### Reference Content
- Decide whether to create standalone reference articles or embed them
- Ensure clear, consistent, and beginner-friendly presentation
- Use suitable formats (lists, tables, or headings) for information display

### Conceptual Content Guidelines
- Begin with **About [topic]**
- Explain purpose and use cases simply with practical examples
- Include prerequisites and next steps for readers

### Error Reference Content Guidelines
- Help users recognize and understand issues clearly
- Separate troubleshooting from known issues
- Document errors transparently with solutions

### Tutorial Content Guidelines
- Define target audience and learning goals upfront
- Use clear developer tone with code examples
- Anticipate common questions and summarize accomplishments

### Getting Started Content Guidelines
- Provide concise, step-based quick-start (under 600 words)
- Include prerequisites, troubleshooting tips, and next steps

### Content Organization
- Follow unified content model with clear document types (Concept, Reference, Procedure)
- Keep structure simple and navigable, avoid overly deep hierarchies
- Organize logically: Concept → Reference → Setup → Usage → Troubleshooting

### Title Standards
- Use task-based gerund titles that are general and scalable
- Keep titles clear, descriptive, and concise (max 80 characters, ideally 60)

### Introduction Standards
- Write 1-2 sentence intro with context and keywords
- Avoid repeating title terms

### Process Content Standards
- Write procedural content as clear, step-by-step, task-oriented instructions
- State permissions upfront using format: "People with [role] can [action]"

### Reusability Standards
- Use reusable text variables to avoid duplicate content
- Mark product-specific features clearly with labeled notes and links
